# LouieLabs Wildlife Cam — HT-HC33 core override (boards.local.txt)
#
# The Arduino IDE automatically loads this file alongside the Heltec core's
# boards.txt and lets it override values. It forces the HT-HC33 to use the FULL
# 16MB of flash (the factory config only used 8MB) and warns early if a sketch
# is bigger than one 2MB app slot.
#
# IMPORTANT: the partition LAYOUT is NOT set here. The Heltec core copies
# variants/HT-HC33/partitions.csv into every build, and that file outranks any
# build.partitions / "Partition Scheme" setting. So the OTA layout is forced by
# replacing that variant file (see variants/HT-HC33/partitions.csv in this repo
# folder), and this file only handles the flash SIZE and the size guard.
#
# "Force" mode (no Tools-menu dropdowns) is intentional: it makes the layout
# student-proof so nobody can accidentally wipe stored photos.
#
# A MANUAL core reinstall removes this file AND restores the factory variant
# table. The source of truth lives in the repo at firmware/heltec-core-overrides/
# — re-copy BOTH after any reinstall. See README.md in that folder.

HT-HC33.build.flash_size=16MB
HT-HC33.upload.maximum_size=2097152

# PSRAM is deliberately NOT forced here (yet) -- read this before "fixing" it.
#
# The Tools > PSRAM menu defaults to "Disabled", which silently caps the camera
# at 640x480: with PSRAM off the frame buffer has to live in on-chip RAM, which
# can't hold a bigger frame. Every flasher must set Tools > PSRAM by hand (see
# cloud_telemetry_node/README.md), which is exactly the kind of footgun the
# force-mode overrides above exist to remove -- so why isn't it forced?
#
# Two reasons, both resolvable:
#   1. It is not settled whether this board wants "QSPI PSRAM" or "OPI PSRAM".
#      The Heltec core defaults `build.psram_type=qspi`, but the ESP32-S3R8 part
#      normally carries OCTAL PSRAM. Forcing the wrong one would leave PSRAM
#      undetected on every board -- the same silent VGA cap, harder to spot.
#   2. A Tools-menu selection is applied AFTER this file, so a forced value here
#      may be overridden by the menu anyway. Forcing it properly means
#      redefining the menu options themselves, which is worth doing once, not
#      guessing at twice.
#
# The firmware fails safe in the meantime: it calls psramFound() at runtime,
# drops to VGA if PSRAM is missing, and says so on the serial monitor.
#
# TO FINISH THIS: flash a board, read the serial log, note which menu choice
# yields "[cam] PSRAM found", then force that value here and delete this block.
